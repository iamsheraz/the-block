# Story 1.1 — Data layer with first UI render

**Status:** Ready
**Estimate:** 105 min
**Depends on:** Story 1.0

## Story

Stand up the data layer behind the `dataStore` interface and prove it works by replacing the Story 1.0 placeholder with a simple unstyled vehicle list. TDD on `validateBid` — the only piece of real business logic in the app. Every downstream story consumes what this story builds.

## Files touched

- `src/lib/constants.ts` — `MIN_BID_INCREMENT`, `MAX_BID`, `AUCTION_DURATION`, `ENDING_SOON_THRESHOLD`, `AWAY_THRESHOLD`
- `src/lib/timestamps.ts` — median-anchor normalization, `getAuctionStatus(vehicle, now)`
- `src/lib/dataStore.ts` — `DataStore` interface + localStorage implementation
- `src/lib/bids.ts` — `validateBid` pure function
- `src/hooks/useNow.ts` — single-clock `useSyncExternalStore`
- `src/hooks/useVehicles.ts`, `src/hooks/useBids.ts`
- `src/pages/LandingPage.tsx` — **update** to render unstyled list of 20 vehicles
- Tests: `timestamps.test.ts`, `bids.test.ts` (TDD), `dataStore.test.ts`

## Acceptance criteria

- **AC1** `dataStore.getVehicles()` returns 200 vehicles with `auction_start` timestamps normalized via median-anchor offset. The JSON file on disk is never mutated.
- **AC2** `getAuctionStatus(vehicle, now)` returns `'upcoming' | 'live' | 'ended'` correctly: upcoming when `now < auction_start`, live when in `[auction_start, auction_start + AUCTION_DURATION]`, ended after.
- **AC3** `validateBid` returns a `BidResult` discriminated union. Rejects amount `<= current_bid`, amount `> MAX_BID`, and any bid when status is not `live`. Accepts amount `>= starting_bid` when `current_bid` is null. Accepts amount `>= current_bid + MIN_BID_INCREMENT` otherwise.
- **AC4** `dataStore.submitBid` persists to localStorage under one key, replays on cold start, and fires subscribers via `useSyncExternalStore`.
- **AC5** `useNow()` ticks once per second and re-renders subscribers via `useSyncExternalStore`. Tests can fake the clock.
- **AC6** `LandingPage.tsx` renders an unstyled `<ul>` of the first 20 vehicles, each `<li>` showing `{year} {make} {model} — {auction_status}`. The status text updates live as the clock ticks across status thresholds.

## Tests (TDD on `validateBid`)

Write these tests first; they all fail. Then implement `validateBid` until they pass.

- `validateBid rejects amount equal to current_bid`
- `validateBid rejects amount below current_bid + MIN_BID_INCREMENT`
- `validateBid rejects amount above MAX_BID`
- `validateBid rejects when auction status is upcoming`
- `validateBid rejects when auction status is ended`
- `validateBid accepts amount equal to starting_bid when current_bid is null`
- `validateBid accepts amount equal to current_bid + MIN_BID_INCREMENT`

Additional tests (after implementation):

- `normalizeTimestamps shifts the median to "now" for an arbitrary dataset`
- `getAuctionStatus returns the correct status across the three windows`
- `dataStore.submitBid persists and replays across a fresh module load`

## How to verify (UI)

1. `npm run dev`
2. Browser opens http://localhost:5173 — see the heading from 1.0 plus an unstyled list of 20 vehicle rows.
3. Each row shows year, make, model, and auction status (Upcoming / Live / Ended). Roughly a third of each status type, balanced around "now".
4. Wait a minute — at least one row's status text should change as auctions transition.
5. `npm run test` — all unit tests pass, including the TDD bid validation suite.

## Watch for / Notes

- The unstyled list is a temporary surface to prove wiring. Story 1.2 replaces it with the styled card grid.
- If the page shows mostly "Ended" statuses, median-anchor normalization is probably off. The median of the unmodified `auction_start` values across the dataset should land at roughly `now` after the offset is applied.
- LocalStorage persists across dev sessions. Use the dev-tools "Application" tab to clear it between test runs if bids stack up.
- `useNow()` is the single clock for the whole app. No other component should own a `setInterval`.
