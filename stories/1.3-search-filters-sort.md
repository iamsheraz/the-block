# Story 1.3 — Search, filters, sort, ending-soon strip

**Status:** Done
**Estimate:** 105 min
**Depends on:** Story 1.2

## Story

Layer the inventory interactions on top of the grid: fuzzy search across make / model / VIN / lot; three filters (make, body type, price range); a sort dropdown; an "ending soon" strip above the grid for vehicles in their last hour. All filter and sort state is URL-synced so links are shareable and the back button works.

## Acceptance criteria

- **AC1** Search input matches make / model / trim / VIN / lot, case-insensitive, typo-tolerant via Fuse.js. Debounced 200ms.
- **AC2** Three filters render and compose: make (multi-select dropdown), body type (multi-select chips), price range (min/max number inputs).
- **AC3** Sort dropdown options: Ending Soon (default), Recently Added, Price Low→High, Price High→Low, Condition Best→Worst.
- **AC4** All filter, search, and sort state lives in URL query params. Refresh preserves state. Browser back/forward restores prior state. A "Clear filters" button resets the URL to defaults.
- **AC5** Result count renders above the grid (`Showing N of 200 vehicles`). When N=0, the grid is replaced by an empty-state message with the "Clear filters" CTA prominent.
- **AC6** Ending-soon strip renders above the grid showing up to 5 vehicles where `time_remaining < ENDING_SOON_THRESHOLD` (1 hour). Hidden if no vehicles qualify. Independent of the active filter — always shows globally ending-soon items.

## How to verify (UI)

1. `npm run dev` — visit `/`.
2. Type "Honda" in search — results filter to Honda vehicles. URL becomes `/?q=Honda`.
3. Click into a vehicle and back — filter is preserved.
4. Refresh the page — filter is still applied.
5. Copy the URL, paste in a new tab — same filtered results.
6. Select "SUV" in body filter — results narrow further. URL gains `&body=SUV`.
7. Click "Clear filters" — URL returns to `/`, all 200 cards visible.
8. Type "Civc" (typo) — Civics still match (Fuse tolerance).
9. Set price max to 15000 — only cards with price ≤ $15k.
10. Set filters that match nothing — empty state with "Clear filters" CTA appears.
11. The "Ending Soon" strip renders above the grid showing live auctions ending within an hour. Time chips count down in real time.

## Watch for / Notes

- The URL is the source of truth. Components read and write through `useFilters()`, never `useSearchParams` directly outside that one hook.
- Debounce the search input but write to URL on every change — debouncing the URL write would break the back-button experience.
- Fuse.js threshold tuned by feel for now; documented in `ARCHITECTURE.md` as a follow-up to benchmark.
- The ending-soon strip is its own urgency surface independent of sort — even if a buyer sorts by "Price Low→High", the strip stays visible and time-ordered.

## Dev Agent Record

### Implementation Plan

- Pure logic first (`src/lib/filters.ts`): structured filter + Fuse.js fuzzy search + sort, all driven by a single `applyFilters(vehicles, state, now)` entry point. Sort key extended with `recently-added` (proxied via descending `lot` since the dataset carries no `listed_at`).
- URL ↔ state seam (`src/hooks/useFilters.ts`): the only module that touches `useSearchParams`. Defaults stripped from the URL so `?` stays empty when filters are at rest; unknown sort values fall back to default.
- UI surfaces (`SearchBar`, `FilterBar`, `SortSelect`, `EndingSoonStrip`) are dumb props-driven components. The page glues them together with `useFilters()` and runs `applyFilters` through `useDeferredValue` for snappy typing.
- Strip independence: `EndingSoonStrip` reads the unfiltered `useVehicles()` list so urgency stays visible even when the buyer narrows the grid.

### Completion Notes

- AC1 satisfied via Fuse.js (`keys: make, model, trim, vin, lot`, threshold 0.35, `ignoreLocation: true`). Typo case `Civc → Civic` and partial-VIN match both covered by `filters.test.ts`.
- AC2: make multi-select dropdown with checkbox rows, body-style chip toggles, price min/max number inputs. Filters compose AND-style across categories, OR-style within each category.
- AC3: sort dropdown options match the brief plus `Recently Added`. The default key (`ending-soon`) is stripped from the URL.
- AC4: every filter/search/sort field round-trips through `useSearchParams`. `Clear filters` resets the URL to defaults. Verified via `useFilters.test.tsx` and `InventoryPage.test.tsx` URL-driven scenarios.
- AC5: result count line renders above the grid; empty state replaces the grid with its own prominent `Clear filters` CTA.
- AC6: `EndingSoonStrip` filters to live auctions in the final hour, sorts soonest first, caps at five. Hidden entirely when nothing qualifies. The component subscribes to `useNow()` via its parent so the MM:SS countdown ticks every second.
- React 19 `useDeferredValue` wraps the parsed filter state so the search input stays responsive while Fuse re-runs in a low-priority transition. URL writes are immediate to preserve back/forward correctness (see `Watch for / Notes`).
- All 111 unit tests green; `npm run verify` (typecheck + biome + vitest + production build) passes.
