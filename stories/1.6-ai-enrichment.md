# Story 1.6 — AI condition summary enrichment

**Status:** Ready
**Estimate:** 90 min
**Depends on:** Story 1.4 (for `ConditionSummary` to mount on the VDP)

## Story

Replace the placeholder text in `ConditionSummary` with real AI-generated two-sentence condition narratives, baked into the dataset at build time. The script calls Claude Haiku 4.5 once per vehicle with a system prompt that forbids price claims, repair-cost estimates, and appraisal-adjacent language — the compliance guard for a regulated dealer context.

## Files touched

- `scripts/enrich.mjs` — new build-time script using `@anthropic-ai/sdk`
- `data/vehicles.json` — gets enriched in place; committed after run
- `src/components/ConditionSummary.tsx` — update to render `vehicle.ai_summary`
- `src/types.ts` — add optional `ai_summary?: string` field to `Vehicle`
- `package.json` — `scripts.enrich`, `@anthropic-ai/sdk` dependency
- `.github/workflows/ci.yml` — add coverage check step
- `.env.example` — document `ANTHROPIC_API_KEY` for the script

## Acceptance criteria

- **AC1** `npm run enrich` reads `data/vehicles.json`, calls Claude Haiku 4.5 once per vehicle. Each call passes the vehicle's condition fields (`condition_grade`, `condition_report`, `damage_notes`, `odometer_km`, `title_status`, `year`, `make`, `model`) and writes an `ai_summary` string back into the JSON.
- **AC2** System prompt encodes five rules: (1) two sentences max, (2) describe condition story (grade, mileage context, damage themes), (3) **no dollar amounts, repair-cost estimates, market values, or appraisal-adjacent claims**, (4) no resale or wholesale price predictions, (5) mechanical concerns named generically ("reconditioning work," "diagnosis recommended") with no cost quantification.
- **AC3** Script is **idempotent**: vehicles with an existing `ai_summary` are skipped unless `--force` flag is passed. Failed API calls retry with exponential backoff up to 3 attempts.
- **AC4** Script exits non-zero if any vehicle is missing `ai_summary` after the run (coverage gate). A CI workflow step runs `node scripts/enrich.mjs --check` to verify coverage on the committed dataset.
- **AC5** Output validation: the script rejects and retries any generated summary containing a `$` character, the words "estimated cost", "market value", "appraised at", or numeric repair amounts. After 3 retries, the vehicle is logged and the script exits non-zero.
- **AC6** `ConditionSummary` component reads `vehicle.ai_summary` and renders it inside the `BidPanel` (slot defined in Story 1.4). If `ai_summary` is missing, falls back to a templated sentence derived from `condition_report` and `damage_notes` count.
- **AC7** The Anthropic API key is read from `process.env.ANTHROPIC_API_KEY` in the script only. Never imported by any file in `src/`.

## System prompt for `scripts/enrich.mjs`

```
You write two-sentence condition summaries for used vehicles in a wholesale
auction listing. Given the vehicle's condition fields, write a summary that
helps a professional buyer assess risk in under 30 seconds.

Rules:
1. Exactly two sentences.
2. Describe condition (grade context, mileage context, damage themes).
3. Do NOT include dollar amounts, repair-cost estimates, market values,
   appraisal claims, or any numeric figures other than the grade or mileage.
4. Do NOT predict resale or wholesale price.
5. Mechanical concerns must be named generically — "reconditioning work,"
   "diagnosis recommended" — never quantified by cost.

Output only the two-sentence summary. No preamble, no quotes, no labels.
```

## Tests

- Smoke run against a fixture of 3 representative vehicles (clean, rebuilt, salvage).
- Output validator: assert no `$`, no "estimated cost", no "appraised", no four-digit numbers other than mileage and year.
- `ConditionSummary renders ai_summary when present`
- `ConditionSummary renders templated fallback when ai_summary is missing`

## How to verify (UI)

1. Set `ANTHROPIC_API_KEY` in your local `.env` file.
2. `npm run enrich` — script runs through 200 vehicles (~2-3 minutes with rate limits). Console logs each completion.
3. Re-run `npm run enrich` — script reports "all vehicles already enriched, skipping" and exits zero (idempotency check).
4. Open `data/vehicles.json` — every vehicle has an `ai_summary` field with a two-sentence description.
5. Grep the file for `$` — only price fields contain `$`, never inside `ai_summary` strings.
6. `npm run dev` — visit any `/vehicle/:id`.
7. The bid panel now shows real AI summary text replacing the Story 1.4 placeholder.
8. Try a vehicle whose `ai_summary` you manually delete and reload — the templated fallback renders cleanly.

## Watch for / Notes

- This story **depends on Story 1.4** because `ConditionSummary` lives inside the VDP's bid panel.
- The compliance guard (no price figures) is enforced **twice**: in the system prompt as instruction, and in the script as output validation with retry. Defense in depth.
- The Anthropic API key never leaves the build environment. The committed JSON contains the static summaries; the client bundle has no API code.
- Re-running enrichment is cheap (skips already-done vehicles). Use `--force` only when you want to regenerate everything (e.g., after a prompt change).
- For local dev without an API key, the templated fallback in `ConditionSummary` keeps the UI functional — the AI summary is an enhancement, not a blocker.
