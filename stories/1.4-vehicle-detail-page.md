# Story 1.4 — Vehicle Detail Page (trust triptych)

**Status:** Review
**Estimate:** 120 min
**Depends on:** Story 1.2 (for routing wired)

## Story

Build the hero screen — the page where the buyer actually decides. Above the fold: the trust triptych of image gallery, condition + damage diagram + mechanical concerns, and bid panel with AI summary placeholder and CarFax link. Below the fold: full specs, damage notes detail, seller info, buyer's own bid history. This is the most visually involved story and the screen that earns the rubric's "craft" points.

## Acceptance criteria

- **AC1** `/vehicle/:id` renders two columns above the fold: image gallery on the left, condition + damage diagram + mechanical concerns in the right column. Below ~900px the columns stack vertically in trust order: gallery → condition + diagram → mechanical → bid panel.
- **AC2** `ConditionHero` shows numeric grade badge + one-word interpretation: ≥4.5 "Excellent", 3.5–4.5 "Above Average", 2.5–3.5 "Average", 1.5–2.5 "Below Average", <1.5 "Poor".
- **AC3** `DamageDiagram` renders an SVG body silhouette with one dot per body-classified damage note. Dot position derived from `damage.mapToRegion(note)` keyword heuristic. Each dot has a hover tooltip showing the full note text.
- **AC4** `MechanicalConcerns` renders below the diagram as a labeled panel: heading shows `⚙ MECHANICAL CONCERNS (N)` with the count; bullets list each mechanical-classified note. Panel hides if N=0.
- **AC5** `BidPanel` renders below the two columns, full-width: time chip, "Starts at" or "Current bid" line, reserve status if applicable, `ConditionSummary` placeholder, CarFax outbound chevron link, bid input + Place Bid button (button is disabled in this story; handler wired in 1.5).
- **AC6** Below the fold: `SpecsGrid` (engine, trans, drive, ext color, int color, VIN, title), `DamageNotesList` (both body and mechanical lists, each note resolved to plain language), `SellerBlock` (dealership name + city/province), `BidHistory` (empty state by default).
- **AC7** `ImageGallery`: hero image left, thumbnail strip below. Clicking a thumbnail swaps the hero. Arrow keys navigate when the gallery has keyboard focus. `onError` on every image falls back to a styled placeholder.
- **AC8** Navigating to an invalid `:id` renders a not-found state with a link back to inventory.

## How to verify (UI)

1. `npm run dev` — visit `/`.
2. Click any vehicle card — navigates to `/vehicle/:id`.
3. Above the fold: see two columns. Left column has the hero image and thumbnail strip. Right column has the grade badge with interpretation, then the SVG damage diagram with body-region dots, then the mechanical concerns panel.
4. Hover any damage dot — tooltip shows the full note text.
5. Below the fold: see specs grid, damage notes detail list, seller info, "No bids placed yet" history.
6. Click a thumbnail in the gallery — hero image swaps.
7. Press Tab to focus the gallery, then arrow keys to navigate.
8. Resize the window to below 900px — the two columns stack vertically, preserving trust order.
9. Find a vehicle with no damage notes — diagram is empty, mechanical panel is hidden.
10. Find a vehicle with a salvage title — title status shows in the page header beneath the breadcrumb.
11. Navigate to `/vehicle/does-not-exist` — see a not-found state with a link back.

## Dev Agent Record

### Implementation notes

- React Router v7's `lazy` route property only applies in Data Mode (`createBrowserRouter`). The app uses declarative `<Routes>`, so the detail page is code-split with `React.lazy()` + `Suspense` in `src/App.tsx`. Because the module ships a **named** export (per CLAUDE.md), the dynamic import is re-shaped: `lazy(() => import('./pages/VehicleDetailPage').then((m) => ({ default: m.VehicleDetailPage })))`. The build produces a separate `VehicleDetailPage-*.js` chunk (~23 kB).
- `damage.ts` is two pure pieces: `classifyNote` (mechanical keyword list, otherwise body) and `mapToRegion` (ordered keyword rules → region key → SVG coordinate). SVG positions are anchored to a top-down silhouette with viewBox `0 0 220 340`, matching the mockup. Notes that cite a side ("driver-rear wheel well") resolve to the specific corner; the generic phrasing ("rust on wheel wells") resolves to a midpoint `wheels-rear` so a single note still produces a single dot per AC3.
- `DamageDiagram` jitters dots that resolve to the same region so two notes mapped to the same point don't overlap pixel-for-pixel. Tooltips use the SVG `<title>` element — native to circles, accessible to screen readers, and triggers a browser tooltip on hover.
- `BidPanel` ships the UI scaffold with a disabled "Place bid" button (handler lands in 1.5). The bid input is uncontrolled-ish (local draft state) so the field is live, just non-actionable. Time chip is the existing `TimeChip` component fed by `useNow()` from the page.
- `ConditionSummary` flags itself as a placeholder until story 1.6 wires real AI text into `vehicle.condition_report`. The placeholder copy explicitly names the next story.
- Invalid `:id` → not-found state (`AC8`) is rendered inside the same lazy-loaded page module, so it falls under the Suspense boundary.
- Library APIs verified live before coding: React Router v7 declarative routing requires `React.lazy()` + `Suspense` (not `<Route lazy>`); React 19 `lazy` still requires a `default` export shape; Vitest 3 retains the `vi.useFakeTimers` API (unused in this story but checked).
