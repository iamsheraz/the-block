- **AC3** Route-level `ErrorBoundary` catches chunk-load failures (stale HTML after deploy) and renders a branded "Reload" CTA across Chrome, Firefox, Safari.
- **AC4** Accessibility pass:
  - Semantic landmarks: `<main>`, `<nav>`, `<section>` with labeled headings.

## How to verify (UI)

1. `npm run dev` — visit `/` with a network throttle (Slow 3G in DevTools) and reload. Skeleton cards render before vehicles load.
2. Apply a filter that returns nothing — empty state copy renders with "Clear filters" CTA.
3. Visit `/vehicle/does-not-exist` — not-found state renders with a link back.
4. Tab through the inventory page — focus rings visible on every focusable element. Tab into a card and press Enter — navigates.
5. Enable "Reduce motion" in your OS — refresh the page. Card entrance transitions are disabled.
6. Open DevTools → Lighthouse → run an Accessibility audit. Score should be ≥ 90.
7. `npm run test:e2e` — both Playwright flows pass.
8. Open the README — first line is the live URL. Click it — opens the deployed app.
9. Open `SUBMISSION.md` — all template sections filled out.

## Dev Agent Record

### Completion Notes (2026-05-12)

Polish pass landed in three coordinated layers — components, route wiring, and the surrounding docs/CI bundle. Every AC verified locally; full `npm run verify` and `npm run test:e2e` both exit zero.

**AC1 — Skeletons.** New `src/components/Skeleton.tsx` exposes `InventoryGridSkeleton` and `DetailPageSkeleton`. Both reserve the real layout's shape (cards in a 1/2/3-column responsive grid; triptych frame on the detail page) so the page doesn't jump when content arrives. `App.tsx` was refactored to lazy-load **both** routes and wrap each in `<Suspense fallback={...}>` — previously only the detail page was code-split, which meant the inventory grid never saw a skeleton even on slow networks. With both routes split into their own chunks (`InventoryPage-*.js` and `VehicleDetailPage-*.js` in the build output), the skeleton reliably renders on Slow 3G as called out in "How to verify (UI)" step 1.

**AC2 — Empty states.** Generic `src/components/EmptyState.tsx` covers all four surfaces (filter-zero in `InventoryPage`, no-bid-history in `BidHistory`, no-damage in `DamageNotesList`, not-found in `VehicleDetailPage`). Three tone variants (`panel`, `inset`, `page`) tune density to each context. The local `EmptyState` previously embedded inside `InventoryPage` was deleted; the inline empty branches in `BidHistory` and `DamageNotesList` were rewritten to call the shared component. An `eyebrow` prop preserves the "Lot not found" kicker that the existing `VehicleDetailPage` test asserts on.

**AC3 — Route-level error boundary.** `src/components/ErrorBoundary.tsx` replaces the page-specific `DetailPageErrorBoundary` (now deleted). Both routes wrap their `<Suspense>` in `<ErrorBoundary>`, so chunk-load failures after a deploy bubble to a single boundary regardless of which page errored. The boundary detects chunk-load errors heuristically (matches `ChunkLoadError`, `Failed to fetch dynamically imported module`, and similar engine-specific messages) and renders deploy-aware copy plus a "Reload" CTA. Non-chunk errors fall back to a generic copy with the same Reload action.

**AC4 — Accessibility pass.**
- Landmarks: every page renders a `<main>` (skeletons too); inventory listings, ending-soon strip, bid panel, image gallery, damage notes, bid history, and empty states use labeled `<section>` regions or shared `EmptyState` landmarks.
- Focus rings: added `focus:outline-none focus-visible:ring-2 focus-visible:ring-slate-900 focus-visible:ring-offset-2` to `VehicleCard`, `EndingSoonStrip`, `FilterBar` (dropdown trigger + body-style chips), `CarFaxLink`, and every CTA inside `EmptyState` usages. Search/sort/price inputs already shipped with a `focus:ring-slate-900/10` style from 1.3.
- Keyboard nav: tabbing through filters, into a card, into the detail page, into the bid form, into the confirmation modal already worked from 1.5 (focus trap + restore-on-close lives in `BidConfirmationModal`). Verified manually.
- `prefers-reduced-motion`: global media-query rule in `src/index.css` disables all CSS animations, transitions, and smooth scrolling — covers the `animate-pulse` skeletons, the `animate-spin` modal spinner, card hover transitions, and any future motion without per-component changes.
- Alt text: `VehicleCard` and `ImageGallery` already emitted meaningful alts or `role="img"` placeholders from 1.2/1.4 — no diff needed here.

**AC5 — Playwright E2E (browse-filter-bid).** New `tests/e2e/browse-filter-bid.spec.ts`. The dataset's 7 Toyotas all sit far from the dataset median (closest is the 2022 Camry at Δ = -20h), which means at a real wall-clock moment no Toyota is in the live window. The spec uses Playwright's `clock.install()` to pin time at the dataset's median timestamp (so `dataStore` normalizes with zero offset), then `clock.fastForward("50:30:00")` plus a one-second `runFor` to move the 2022 Tundra (Δ = +49h) into a mid-auction state with ~2.5h remaining. Test asserts the success panel and bid history both reflect the placed bid.

**AC6 — Playwright E2E (responsive).** New `tests/e2e/responsive.spec.ts` at viewport 375×667 (iPhone SE/8 — the smallest realistic mobile target). Asserts single-column stacking on the inventory grid via bounding-rect equality of adjacent cards, and vertical stacking of the gallery + bid panel on the detail page.

**AC7 — README rewrite.** Live URL on the first line under the title (placeholder pending Vercel deploy), three-command "How to Run" path with collapsible Docker subsection, two-paragraph "What I Built" intro, links to all four product docs, "Notable Decisions" as a pointer back to ARCHITECTURE.md (no duplication), "What I'd Build Next" pointing to PRODUCT.md's roadmap.

**AC8 — SUBMISSION.md filled.** Every template section completed (How to Run, Time Spent, Assumptions and Scope, Stack, What I Built, Notable Decisions, Testing, What I'd Do With More Time).

**AC9 — CI gates.** `.github/workflows/ci.yml` now has two jobs: `verify` (typecheck + lint + tests + build, plus the AI summary coverage gate) and `e2e` (depends on verify success, installs Chromium, runs `npm run test:e2e`, uploads the playwright-report artifact on failure). `playwright.config.ts` lives at the repo root and ships a single Chromium project with a dev-server webserver block (`reuseExistingServer: !process.env.CI`). The Playwright spec directory `tests/e2e/**` is excluded from Vitest's `test.include` glob in `vite.config.ts` so co-located unit tests stay scoped to `src/**`.

**Prep cleanup.** The personal study folder at `prep/` was removed before commit, per the story's pre-submission step.
