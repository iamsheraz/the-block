## Acceptance criteria

- **AC1** Skeleton screens render for the inventory grid (card-shaped gray boxes) and the vehicle detail page (gallery + triptych skeleton) during initial load.
- **AC2** Empty states designed and copied: filter-zero-results, no bid history ("No bids placed yet"), no damage notes on a vehicle ("No reported damage"), not-found page for invalid `/vehicle/:id`.
- **AC3** Route-level `ErrorBoundary` catches chunk-load failures (stale HTML after deploy) and renders a branded "Reload" CTA across Chrome, Firefox, Safari.
- **AC4** Accessibility pass:
  - Semantic landmarks: `<main>`, `<nav>`, `<section>` with labeled headings.
  - Focus rings visible on every interactive element.
  - Keyboard navigation works end-to-end: tab through filters, into a card, into the detail page, into the bid form, into the confirmation modal.
  - Modal traps focus, restores on close (already shipped in 1.5; verify here).
  - `prefers-reduced-motion` honored — card entrance transitions and animations are disabled when the user has reduced motion enabled.
  - All `<img>` tags have meaningful `alt` text (or `alt=""` for purely decorative).
- **AC5** Playwright E2E flow 1 (`browse-filter-bid.spec.ts`): visit `/`, type "Toyota" in search, click the first result card, observe the detail page, enter a valid bid in the panel, click Place Bid, confirm in modal, verify the success state shows the new high bid and the bid history lists the bid.
- **AC6** Playwright E2E flow 2 (`responsive.spec.ts`): visit `/` at 375×667 viewport, verify the grid is single-column, verify the filter button collapses filters into a sheet, navigate to a detail page, verify the triptych stacks vertically in trust order.
- **AC7** README rewritten with:
  - Live Vercel URL as the first line under the title.
  - "How to Run" section with three commands max for the npm path, plus an optional Docker subsection.
  - Two-paragraph "What I Built" intro.
  - Links to `PRODUCT.md`, `ARCHITECTURE.md`, `UX.md`, `STORIES.md`.
  - "Notable Decisions" pointer to ARCHITECTURE.md (don't duplicate).
  - "What I'd Build Next" section pointing to `PRODUCT.md`'s roadmap.
- **AC8** `SUBMISSION.md` filled out using the template structure: How to Run, Time Spent, Assumptions and Scope, Stack, What I Built, Notable Decisions, Testing, What I'd Do With More Time.
- **AC9** `npm run verify` and `npm run test:e2e` both exit zero in CI. CI workflow runs `verify` as a fast pass, then `test:e2e` as a slower job gated on `verify` success.

## How to verify (UI)

1. `npm run dev` — visit `/` with a network throttle (Slow 3G in DevTools) and reload. Skeleton cards render before vehicles load.
2. Apply a filter that returns nothing — empty state copy renders with "Clear filters" CTA.
3. Visit `/vehicle/does-not-exist` — not-found state renders with a link back.
4. Tab through the inventory page — focus rings visible on every focusable element. Tab into a card and press Enter — navigates.
5. Enable "Reduce motion" in your OS — refresh the page. Card entrance transitions are disabled.
6. Open DevTools → Lighthouse → run an Accessibility audit. Score should be ≥ 90.
7. `npm run test:e2e` — both Playwright flows pass.
8. Open the README — first line is the live URL. Click it — opens the deployed app.
9. Open `SUBMISSION.md` — all template sections filled out.

## Watch for / Notes

- Order within this story: polish first (skeletons, empty states, a11y), then E2E (write the flows against the polished UI), then docs (the live URL in the README will only be honest after the final deploy).
- The README's first line should be the Vercel URL, formatted prominently. Reviewers click before they read.
- `SUBMISSION.md` is the document the OPENLANE evaluator reads end-to-end. Quality matters here more than anywhere else in the doc bundle.
- Lighthouse accessibility ≥ 90 is the bar, not 100 — perfect a11y in 30 minutes is unrealistic, and the rubric isn't a WCAG audit. The honest claim is "semantic markup, keyboard accessible, motion-respectful — no full audit."
- Before submitting: `rm -rf prep/` and verify the folder is gone before pushing.
