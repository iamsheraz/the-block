# Story 1.0.5 — Docker setup (optional)

**Status:** Done
**Estimate:** 45 min
**Depends on:** Story 1.0

## Story

Add an optional Docker setup for local development so contributors can run the dev server without managing a Node version on their host. The npm path remains the canonical run instruction; Docker is the alternate path documented in the README.

## Files touched

- `Dockerfile`
- `docker-compose.yml`
- `.dockerignore`
- `README.md` — add "Run with Docker (optional)" section
- `vite.config.ts` — optional `usePolling: true` for HMR through volume mounts (commented for opt-in)

## Acceptance criteria

- **AC1** `Dockerfile` based on `node:22-alpine`, copies `package.json` and `package-lock.json` first for layer caching, runs `npm install`, exposes port 5173, defaults to `npm run dev`.
- **AC2** `docker-compose.yml` mounts `./` as `/app` with an anonymous volume protecting `node_modules`; binds host `5173:5173`.
- **AC3** `docker compose up` builds the image (first run only) and starts the dev server. Visiting http://localhost:5173 shows the same landing page as the npm path.
- **AC4** Editing `src/pages/LandingPage.tsx` triggers Vite HMR through the volume mount; the browser updates within 2 seconds.
- **AC5** `.dockerignore` excludes `node_modules`, `.git`, `dist`, `prep/`, `playwright-report/`, `test-results/`.
- **AC6** README has a "Run with Docker (optional)" section with the one-liner `docker compose up` and a note about HMR polling for Mac/Windows hosts.

## Tests

None (infrastructure setup).

## How to verify (UI)

1. `docker compose up` — first run builds the image (~2 min).
2. Browser opens http://localhost:5173 — see the same landing page from Story 1.0.
3. Edit `src/pages/LandingPage.tsx` (change the heading text) and save — the browser reloads within ~2 seconds.
4. `Ctrl+C` to stop; `docker compose down` to clean up.

## Watch for / Notes

- **Optional**, not required. The OPENLANE evaluator will run `npm install && npm run dev` — that path stays primary.
- File-watching across Docker volumes can be slow on Mac and Windows hosts. If HMR doesn't trigger, uncomment the `server.watch.usePolling: true` line in `vite.config.ts`.
- Playwright E2E (Story 1.7) does **not** require Docker — keep those running on the host where they're faster and more stable.
- The dev image is for development only — production deploys via Vercel from `main`.
